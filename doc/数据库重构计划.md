# 数据库逻辑重构计划表

> 目标:① 重构数据库初始化逻辑;② 首次部署自动从零生成数据库(发行包不再自带 .sqlite3 文件);
> ③ 自动创建默认管理员账号(随机密码);④ 持续提醒用户创建自己的管理员并删除默认账号。

## 一、现状摘要(重构基线)

| # | 现状 | 位置 | 问题 |
|---|------|------|------|
| 1 | 发行包自带 `udphub.sqlite3`,`start.sh` 缺库时复制一份 | start.sh:11-14 | "默认状态"自带数据库文件,本次已清除其中遗留管理员,但文件本身仍应移除 |
| 2 | `getDB()` 仅 `sql.Open`,父目录不存在/文件损坏均无处理 | config.go:215 | 首次部署 data 目录缺失直接失败;库损坏时报错晦涩 |
| 3 | DDL 双份维护:`execDDL()`(Go,幂等,全量)与 `db/sqlite.sql`(160行,已漂移:devices 表重复 ssid 列) | init.go:74 / db/sqlite.sql | sqlite.sql 已与实际 schema 不一致,误导维护者 |
| 4 | `updatedb()` 用 `schema_migrations` 表按语句去重执行 | config.go:229 | 机制可用,保留 |
| 5 | 引导判定 `isBootstrapped()` 靠"users 表存在且 adminCount>0"推断 | init.go:37 | 无法区分"首次启动"与"管理员被清空",无引导元数据 |
| 6 | `must_change_pwd` 临时复用 users.routes 字段 | init.go:388 | 语义hack,routes 本是权限路由字段 |
| 7 | 默认管理员随机密码仅打印 stdout,无"删除默认账号"提醒闭环 | init.go:290-341 | 用户不知道该删默认账号,长期使用默认账号有风险 |

## 二、阶段计划表

| 阶段 | 内容 | 主要任务 | 涉及文件 | 验收标准 | 预估 |
|------|------|----------|----------|----------|------|
| **P1** | **数据库打开与自动生成** | 1. `getDB()` 增强:DBfile 父目录不存在则 `os.MkdirAll`;文件不存在时日志输出"检测到首次部署,将自动创建数据库"<br>2. 打开后执行 `PRAGMA integrity_check`,损坏则 `log.Fatal` 明确提示(**不自动删除重建,防数据丢失**)<br>3. 连接串追加 `_busy_timeout=5000`(可选 `_journal_mode=WAL`)<br>4. 支持 `NRL_DBFILE` 环境变量覆盖 conf 中的 DBfile | config.go:215 | 空目录+空 data 目录启动 → 自动建库;损坏库启动 → 报错退出且不破坏原文件 | 1天 |
| **P2** | **发行物清理** | 1. `git rm --cached udphub.sqlite3` 并从磁盘移除,`.gitignore` 增加 `*.sqlite3`<br>2. `start.sh` 删除"cp 自带库"分支,仅保留建目录+复制配置<br>3. Dockerfile 核对:builder 阶段 `COPY . .` 不影响最终镜像(已确认),最终镜像仅含二进制+start.sh<br>4. `deploy.sh` 同步检查 | start.sh、.gitignore、deploy.sh、Dockerfile | 仓库中不再存在任何 .sqlite3;Docker 全新 volume 部署可正常启动 | 0.5天 |
| **P3** | **DDL 单一来源** | 1. 确认 `execDDL()`(Go 侧,幂等全量)为唯一权威 schema 来源<br>2. `db/sqlite.sql` 处理:**删除**(或加"已废弃"头注释),修正文档中指向<br>3. `db/update.sql` 同步清理(25行,与 updatedb() 重复) | init.go:74、db/sqlite.sql、db/update.sql | 全仓库仅剩一处 schema 定义;grep 无残留引用 | 0.5天 |
| **P4** | **引导流程重构** | 1. 新增 `meta` 表(key TEXT PRIMARY KEY, value TEXT):`bootstrapped_at`、`default_admin_id`<br>2. `isBootstrapped()` 改为读 meta 表;`execDDL` 中建 meta 表<br>3. `ensureBootstrap` 最终顺序:purgeLegacy(过渡保留)→ updatedb → execDDL → seedRoles → ensureDefaultAdmin<br>4. `purgeLegacyAdmins()` 保留 1 个版本周期后移除(存量旧库已升级完毕) | init.go、config.go | 二次启动不重复建库/建号;meta 表记录完整 | 1天 |
| **P5** | **默认管理员账号** | 1. 无任何用户时创建默认管理员:callsign=NOCALL(支持 conf 配置)、随机16位密码、`must_change_pwd`<br>2. 密码 banner:stdout 打印(容器场景 `docker logs` 可见)+ 写入首条操作日志<br>3. **must_change_pwd 迁移**:users 表新增 `must_change_pwd INTEGER DEFAULT 0` 列,废弃 routes 字段复用;迁移语句把存量 `routes='MUST_CHANGE_PWD'` 换算成新列并清空 routes;读取处(登录/userinfo/改密)同步切换<br>4. 创建成功后写 meta.default_admin_id,作为"默认账号"标记 | init.go:290、usersDB.go(addUser/updatePassword)、users.go | 首启产生默认管理员并可登录;改密后标记清除;routes 字段不再被滥用 | 1.5天 |
| **P6** | **删除提醒-后端** | 1. userinfo/登录响应增加 `default_admin: true/false`(依据 meta.default_admin_id 与当前用户 id 比对,用户已删除则为 false)<br>2. 删除用户 API:删除默认管理员时清 meta.default_admin_id,操作日志记"默认管理员已删除"<br>3. 保护逻辑:拒绝删除系统中最后一个 admin 角色用户(检查 users.go 现有删除流程,缺则补) | users.go:453附近、usersDB.go | 标志位准确;删除默认账号后标志消失;最后一个 admin 不可删 | 1天 |
| **P7** | **删除提醒-前端** | 1. userinfo 返回 `default_admin=true` 时,布局顶部渲染**常驻黄色警告条**(不可关闭):"当前正在使用系统默认管理员账号,请在【用户管理】创建您自己的管理员账号后删除此默认账号"<br>2. 用户管理页:当前用户为默认账号时,高亮"新建用户"入口<br>3. 默认账号删除自己 → 后端登出 → 前端跳转登录页<br>4. 改密成功后警告条**仍显示**(改密≠删除),仅删除后消失 | www/src(布局组件、userinfo store、用户管理页) | 全流程 GUI 走查通过:登录→警告条→建号→删除→警告消失 | 1.5天 |
| **P8** | **文档与测试** | 1. Readme 部署章节重写:首次启动自动建库、`docker logs` 获取随机密码、默认账号删除指引<br>2. CHANGELOG 补充<br>3. 测试矩阵执行(见下节) | Readme.md、CHANGELOG.md | 测试矩阵全部通过 | 1天 |

## 四、风险与对策

| 风险 | 对策 |
|------|------|
| `must_change_pwd` 挪列导致存量带标记用户失效 | 迁移语句同步换算旧标记;新旧读取逻辑在同一版本内兼容 |
| phone 唯一索引与占位号 00000000000 冲突 | seedAdmin 前检查冲突,冲突时改用随机占位号 |
| 损坏库"自动重建"造成数据丢失 | 明确策略:只报错不重建,运维介入 |
| start.sh 改动影响已部署容器 | 旧部署卷内已有库文件,删除 cp 分支无影响;新部署走自动建库 |
| 默认账号删除后无人能管理 | P6"最后一个 admin 不可删"保护先行落地 |

## 五、待确认决策点(开工前)

1. **must_change_pwd 存储**:新增独立列(推荐,规范) vs 继续复用 routes 字段(改动最小)?
2. **db/sqlite.sql 去留**:直接删除(推荐) vs 保留为"自动导出的文档"?
3. **提醒强度**:仅常驻横幅(推荐) vs 横幅 + 每次登录弹窗?
4. **默认管理员权限**:允许其执行全部管理功能仅加提醒(推荐) vs 限制其只能建号/改密/删自己?
